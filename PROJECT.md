# Project: Phase E - Advanced Local AI Capabilities, Client Security, and Offline Isolation

## Architecture
Phase E of the LIVA Strategic Upgrade Plan focuses on upgrading local Voice/AI engines, pruning unused WASM packages and assets to support complete offline isolation, localizing external CDN assets, and hardening Tauri client security.

### Module Boundaries
1. **liva-ai-engine**:
   - Voice Engine: `liva-ai-engine/voice_engine.py` (Edge-TTS WebSockets streaming)
   - STT Server: `liva-ai-engine/whisper_stt_server.py` (audio resampling)
2. **liva-ui**:
   - Web Assets: `liva-ui/public/`, `liva-ui/public/assets/`, `liva-ui/widget.html`
   - Dependencies: `liva-ui/package.json`
   - Composables: `liva-ui/src/composables/useFaceTracking.ts`
3. **liva-gateway**:
   - AI Workers: `liva-gateway/src/workers/FlashRankWorker.ts` and `liva-gateway/src/workers/MoonshineWorker.ts`
4. **liva-desktop (Tauri)**:
   - Config: `liva-desktop/src-tauri/tauri.conf.json`
   - Backend: `liva-desktop/src-tauri/src/lib.rs`

## Interface Contracts
### Voice Engine WebSocket API
- Voice engine must yield binary voice chunks directly as they are generated by Edge-TTS over the WebSocket stream rather than buffering the entire audio.

### Whisper STT API
- The STT endpoint must accept WAV audio of any sample rate, validate the rate, and resample to 16kHz before processing if it is 44.1kHz or 48kHz.

### Gateway Workers Tokenizers
- `FlashRankWorker.ts` must use proper Tokenizer encoding.
- `MoonshineWorker.ts` must use proper Tokenizer decoding.

### Tauri Security
- `tauri.conf.json` must specify a restrictive Content Security Policy (CSP).
- Stronghold key derivation in `lib.rs` must use Argon2id KDF.
- Cursor polling must be replaced with event-driven logic to minimize CPU usage.
