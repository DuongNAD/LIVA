Tối ưu hóa Tokio Runtime & Thread-Tuning

W

Asynchronous Worker Threads Configuration

Bound to environment variable LIVA_TOKIO_WORKER_THREADS. Defaults dynamically to the available system parallelism CPU core count (minimum 4). Dedicated entirely to low-latency non-blocking tasks, file system I/O, IPC packet passing, and network events.

B

Asynchronous Blocking Pool Limiting

Configured via LIVA_TOKIO_MAX_BLOCKING_THREADS (capped at 512). Offloads synchronous file access, SQLite transaction commits, and heavy ONNX model sessions into a dedicated thread pool to avoid blocking the main Tokio event loop.

L

LLM Execution Thread Constraints

Controlled by the LIVA_LLM_THREADS setting (default: 4 threads). Restricting the CPU footprint of llama-cpp-2 prevents execution-heavy tensor dot products from completely saturating the CPU cores. This reserves critical clock cycles for real-time audio playback, STT recording, and IPC synchronization.

Rust Engine Runtime Setup
// Configure Tokio multi-threaded asynchronous runtime let worker_threads = std::env::var("LIVA_TOKIO_WORKER_THREADS") .ok() .and_then(|val| val.parse::<usize>().ok()) .unwrap_or_else(|| std::thread::available_parallelism().map(|n| n.get()).unwrap_or(4)); let max_blocking = std::env::var("LIVA_TOKIO_MAX_BLOCKING_THREADS") .ok() .and_then(|val| val.parse::<usize>().ok()) .unwrap_or(512); let rt = tokio::runtime::Builder::new_multi_thread() .worker_threads(worker_threads) .max_blocking_threads(max_blocking) .enable_all() .build() .expect("Failed to build runtime"); // LLM Context Parameters constraints let threads = std::env::var("LIVA_LLM_THREADS") .unwrap_or_else(|_| "4".to_string()) .parse::<i32>().unwrap_or(4); let ctx_params = LlamaContextParams::default() .with_n_threads(threads) .with_n_threads_batch(threads) .with_type_k(KvCacheType::Q8_0) .with_type_v(KvCacheType::Q8_0);
